# A browser that keeps work moving when you step away

**Pane remembers the thread, learns your routines, and gets better as you work.**

Pane is an open-source Chromium browser with a personal agent built into your real session. It can connect work across tabs, meetings, research, files, and terminal; turn ongoing projects into private sites; and run tasks you chose on a schedule.

**Open source. Local-first. Your models. Your machine.**

## Important limits

Pane is early. The vision is larger than the current build, and the boundary matters:

- **Capture is opt-in.** Meeting capture, research mode, and broader browsing learnings do not start until you enable them.
- **Skill generation is staged and early.** Pane can propose drafts from repeated successful runs; it does not yet operate as a mature autonomous self-improvement loop.
- **Scheduled browser work needs Pane running.** If Pane is fully quit or the machine is asleep, browser tasks wait.
- **Profiles, buckets, and personas are separate controls.** Browser profiles provide hard data separation. Context buckets tune retrieval within a profile. Personas tune role and voice.
- **No managed cloud integrations catalog.** Add your own MCP servers in the server-free Pane build.

Roadmap work includes richer proactive delivery, deeper skill improvement and pruning, optional cloud extensions, and page-level Personalised Internet surfaces. See the [implementation plan](https://github.com/abhishek-verma/Pane/blob/main/specs/IMPLEMENTATION-PLAN.md).

## Why a browser

Your work already lives in authenticated tabs, meetings, localhost, dashboards, files, and terminal. A normal chatbot sees what you paste. An external browser agent attaches to part of the session.

Pane makes the agent native to the browser so continuity, capture, permissions, and action share one local runtime. That is what lets the browser preserve a multi-day thread, capture a meeting at the source, expose the real session to a coding agent, and continue scheduled work without a Pane cloud.

## The developer path

The fastest proof is one loop from bug to verified fix:

1. Open **Settings → Pane as MCP** and copy the local MCP URL.
2. Connect your coding agent, for example: `claude mcp add pane <url>`.
3. Ask it to open localhost, reproduce the bug, read the console, edit the granted workspace, and verify the result.

Pane also includes Cowork directly in the browser if you prefer to run that loop from the side panel.

## Built on trust

- **Open source** under AGPL-3.0
- **Local-first** browsing context, memory, captures, and private sites
- **No required Pane account or credits meter**
- **Permissioned capture** with visible recording and domain controls
- **Approvals based on consequence** for external or destructive actions
- **No Pane-operated server required** for the core product

## Built on BrowserOS

Pane is a fork of [BrowserOS](https://github.com/browseros-ai/BrowserOS). BrowserOS supplied the Chromium fork, agent runtime, browser tools, Cowork foundation, and MCP surface.

Pane pursues a different direction: a local personal agent that is the browser, with native capture, Personalised Internet, inspectable memory and skills, and no Pane-operated cloud required for core features. BrowserOS remains an excellent project if its direction fits you better.
