# Pane Layers implementation status

Updated 2026-09-09. The latest combined-PR fixes and verification are recorded in [release review](RELEASE-REVIEW.md); that report supersedes the historical open-gate descriptions below where explicitly noted. **Production integration is implemented for managed Layers, click-to-translate, bounded adaptive page changes, registered public data badges, version history and durable activity. The complete requested feature has not shipped.** LP-00–LP-13 remain the delivery contract; advanced scripts, complete external-provider parity and the remaining release QA are still gates.

## Implemented

- Strict, versioned manifests and exact-origin/path matching; executable capability assessment rejects unsupported automatic inference, universal content/language claims and unavailable adapters. Each Layer pins one configured provider; no silent fallback.
- Profile SQLite store with immutable versions, candidate/active separation, optimistic revisions, policy grants and expiring version/capability-bound verification. Keep commits consent and activation atomically. Pause, site pause, disable, re-enable and reversible deletion are implemented; restoring leaves a Layer disabled. Migration and fallback schemas match.
- Native-owned launch secret transferred through an inherited pipe; the sidecar consumes and closes it before subprocess creation. The bundled extension receives short-lived profile credentials through `browserOS.getLayerCredential`. Authoring sessions receive narrower scoped authorization; public MCP cannot activate a Layer or submit action results.
- Authenticated broker routes and production extension background/content integration. Commands bind actual tab/document/instance/route identities. Durable local cache supports offline disable and pause. Preview expires after five minutes. Navigation, BFCache, prerender, worker restart, provider changes and revocation invalidate action work.
- Packaged managed interpreter for reversible collapse, highlight and persistent action buttons, with ownership tracking, target/work limits and bounded recovery. Saved local effects reapply without a model call.
- Native independent Layers toolbar action and trusted extension popover; sidebar control and library use the same store. UI provides scope/version/action details, verification-gated Keep, enable/disable, global/site pause and Recently deleted recovery. The native popup was also checked through CUA in the new arm64 binary: it opens with the sidebar closed, connects through native credentials, pauses/resumes the current site, dismisses with Escape and reopens with keyboard focus. Multiple-window and full accessibility coverage remain open.
- Shared assess/validate/tabs/inspect/draft/preview/verify/clear-preview tools. Verification observes actual mounted targets, restores/remounts effects and reloads a temporary tab without disturbing the user's original tab/form. Button verification requires a real trusted click, server-accepted typed output and browser rendering evidence; data badge verification requires a fresh rendered source result.
- Isolated API translation/managed-action runner with only the invocation-private structured result tool (generated tasks use the separate private page tools below), bounded steps/tokens/deadline, cancellation, retries/deduplication and full-context checks. No general chat tools, filesystem, browser navigation, history or memory enter this runner. A Claude Code adapter uses a temporary working directory, restricted/safe mode, no built-in tools or MCP servers, a private structured-output channel, explicit model pinning, bounded output/turns and abort-driven process termination. Its installed-CLI and full browser fixture flows now pass; real-account verification remains open. Generated tasks use an authenticated invocation-local MCP endpoint exposing only page_inspect, page_execute_script and complete_page_task. Because Claude safe mode suppresses explicit MCP too, generated sessions use restricted mode, exact allowed tools, empty user settings, disabled memories/skills/hooks/automatic compaction and no general tools. Translation retains safe mode. Results expire from memory after five minutes.
- Translation captures bounded readable blocks, validates every opaque block ID/language, renders text-only parallel output and preserves originals. Cancel, Undo and stale-source cleanup are implemented.
- Adaptive page actions capture fresh opaque section handles on each click. The model proposes bounded collapse/highlight operations; the browser validates the scope, applies and checks actual effects and offers Undo. These effects last for the document session. Forms/editable controls are excluded, changed snapshots are rejected, and overlapping page-change runs serialize. This is a bounded proposal/apply/check implementation; the broader iterative inspect/apply/adjust tool loop is still open.
- Registered `github.repository.stats` data operation fixes the public API destination, GET method, redirect/credential policy and stars/forks projection. No arbitrary URL or caller credentials enter the broker. Visible entity batching, case-insensitive/concurrent deduplication, profile cache, five-minute freshness, backoff, response-size bounds and network limits are implemented. Zero, stale, denied, unavailable and rate-limited states remain distinct. Badges rebind on virtualized node reuse and relative-link base changes; late old-entity results are discarded. Model and deterministic-data invocation budgets are separate. This is public repository coverage only; no LinkedIn API or authenticated connector is claimed. Capability assessment requires an exact registered source and supported trigger.
- Version history is available through the trusted library UI. Inspect an immutable definition and restore it as a draft without replacing the active version; keeping still requires the exact verification receipt. The current site's old active scope remains visible while a differently scoped draft is edited. Site-panel refreshes reject stale asynchronous tab responses.
- SQLite activity migration `0021_layer_activity` records bounded metadata without page text, responses, URLs or credentials. Recent history covers seven days and at most 1,000 retained runs, pruning on reads/writes. Completed/failed/cancelled/interrupted states survive reconnects. In-memory result replay remains five minutes; after server restart an already-started invocation is rejected instead of silently billed again. Library Stop cancels the current invocation through the background broker.
- Focused accessibility checks now cover keyboard search/disclosures, named controls/cards in Chromium’s AX tree, long names/scopes, both RTL viewport bounds, actual 200% tab zoom and settled light/dark contrast. The screenshot is inspected at viewport size because full-page capture clips at browser zoom. Runtime checks cover keyboard Show focus recovery, temporary tabindex cleanup and independent English/Arabic translation direction. The final managed-only fixture passes 37 checks with userscript access unavailable: managed reload verification no longer waits on the script engine. Manual screen-reader, native popup, fullscreen and broader accessibility coverage remain open.
- Canonical `layers`, `layers-managed` and `layers-javascript` skills and thin prompt routing are materialized through the existing native/Claude/Codex skill system. Authoring tools use the shared native/MCP registration path. Claude action adapter testing has progressed separately; Codex private action isolation now passes installed-CLI fixtures; production routing, account budget policy and browser verification remain open.
- Completed scripts now suspend SDK callbacks during BFCache retention and re-attest a fresh action instance before resuming. Native tests preserve the exact owned DOM and draft form without replaying top-level source, reject delayed navigation results, and clean up cached revocations. Managed effects wait for the current manifest on restore. Registered older bootstraps refresh for future visits without rotating identity or executing mounted source again. Rapid-transition and broader lifecycle stress coverage remain open.
- The advanced userscript registry and SDK components are implemented and exercised in the native browser fixture. The registry persists private per-version identities, verifies the canonical SHA-256 version against source, restores registrations and world settings, keeps active/preview versions separate, revalidates actual native documents, and aborts running callbacks on revocation. The SDK requires model requests to start inside a trusted `paneLayer.listen` click/keyboard handler, rejects synthetic clicks even during browser user activation, tracks cleanup and stops tracked work on route changes. The SDK/registry are now wired to advanced authoring, exact-source preview grants, typed action results, declared DOM assertions, temporary-tab reload verification and production Layer controls. JavaScript capability is reported only when the engine is available. The production browser fixture now passes exact-source approval, preview, trusted typed translation, negative DOM verification, Keep, reload persistence, disable cleanup, load-time data actions and infinite-loop recovery. Generated-script page tasks are now connected through the private API action harness; full release qualification still requires external-provider parity and the remaining lifecycle/QA matrix.

- Generated page tasks declare page-task with execution=javascript inside an explicitly approved JavaScript Layer. Their dedicated pane.script-task-input.v1 request exposes only private page_inspect, page_execute_script and complete_page_task tools to the API action runner. Source never travels through the ordinary data-result path. Browser-native document checks, current invocation state, immutable action policy, same-document task serialization and bounded execution protect the dispatch boundary. The authenticated extension handshake reports generated execution independently from userscript access, so older extensions cannot be treated as supporting the new commands. The loop allows at most three sequential script attempts within the saved overall step/token/deadline budget. It returns observed DOM checks, source hashes and reload-required recovery; completion cannot reuse a previous passing result after a later failed edit. The browser fixture exercises inspect, a failing edit, reinspection, repair, completion, exact-version verification, Keep, reload without model work, another trusted click, form preservation and disable cleanup. Scope controls disclose that the grant includes newly generated code. The shared JavaScript skill distributes this contract to every authoring provider. Generated execution now passes through the installed Claude CLI as well as the API adapter; Codex action integration remains open.

## Native UI probe

`bun scripts/dev/layers-native-probe.ts --ui` launches the built native app with a disposable profile, production popup assets and production Layer background/native transport. Provider inventory is an empty fixture and the sidecar contains production Layer routes/auth plus minimal health handling. It writes `/tmp/pane-layers-native-ui.json` with the test PID and a completion path. Native UI automation must verify the toolbar/popup before writing that completion file; the probe then closes its browser and fixture children. This mode is a manual UI verification aid, not a claim that headless automation clicked native chrome. The ordinary command independently verifies the two-launch authentication lifecycle.
